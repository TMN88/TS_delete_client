# TS_delete_client

Удаление клиента Tailscale с OpenWrt по инструкции «удаление ТС.txt». POSIX sh / BusyBox ash, пакетные менеджеры `apk` и `opkg`.

## Запуск

Подключись к роутеру от root через LAN или другой независимый канал: удаление Tailscale прервёт доступ через него.

```sh
wget -O /tmp/delete_tailscale.sh https://raw.githubusercontent.com/TMN88/TS_delete_client/main/delete_tailscale.sh && sh /tmp/delete_tailscale.sh
```

Скрипт запросит слово `DELETE`. Без дополнительного вопроса:

```sh
wget -O /tmp/delete_tailscale.sh https://raw.githubusercontent.com/TMN88/TS_delete_client/main/delete_tailscale.sh && sh /tmp/delete_tailscale.sh --yes
```

Перезагрузка после успешного удаления и проверки:

```sh
sh /tmp/delete_tailscale.sh --yes --reboot
```

## Что удаляется

1. Останавливается Tailscale, отключается служба и её автозапуск. Регистрации `tailscale` и `tailscaled` снимаются с procd через ubus, чтобы исключить перезапуск этим супервизором. Скрипт ждёт завершения до 10 секунд, затем при необходимости отправляет SIGTERM (ожидание до 5 секунд) и SIGKILL (ещё до 5 секунд). Если процесс остаётся, дальнейшее удаление отменяется; выводятся PID и доступные поля Name/State/PPid без командной строки и ключей.
2. Удаляются секции `network.tailscale` и `firewall.tailscale`, изменения сохраняются в UCI.
3. Удаляются установленные пакеты `luci-app-tailscale-community`, `luci-app-tailscale`, `tailscale`, `tailscaled`. Принудительное удаление зависимостей не используется.
4. Удаляются `/etc/hotplug.d/iface/95-tailscale`, ссылки `/etc/rc.d/*tailscale` и `*tailscaled`, настройки `/etc/config/tailscale`, `tailscaled` и стандартные резервные файлы настроек.
5. Полностью удаляются выделенные каталоги `/etc/tailscale`, `/var/lib/tailscale`, `/var/run/tailscale`, `/run/tailscale`, включая ключи состояния. В том числе удаляются оба файла из инструкции: `/etc/tailscale/tailscaled.state` и `/var/lib/tailscale/tailscaled.state`. Содержимое выделенных каталогов, включая возможные локальные данные Taildrop, тоже удаляется.
6. Удаляются `/var/run/tailscaled.sock`, `/var/run/tailscaled.pid`. После успешного удаления пакетов очищаются оставшиеся init-скрипты и исполняемые файлы Tailscale в `/usr/bin` и `/usr/sbin`.
7. При изменении UCI применяется сеть и перезапускается firewall. Проверяется отсутствие `tailscale0`; при необходимости скрипт пытается удалить оставшийся интерфейс.

Каталоги `/etc/config` и `/etc/init.d` целиком **не удаляются**: в них находятся настройки других служб. Из них удаляются только перечисленные файлы Tailscale.

Скрипт не меняет прошивку, другие VPN, пользовательские DNS-настройки или запись устройства в серверной панели tailnet.

## Итоговый отчёт

Неоновые цвета ANSI: бирюзовый заголовок, фиолетовая рамка, зелёные успешные результаты, красные ошибки, жёлтые уведомления. В обычном терминале цвета включаются автоматически; `--color` включает принудительно, `--no-color` или переменная `NO_COLOR` отключает автоматическое оформление.

В конце проверяются и выводятся отдельно:

- служба остановлена;
- пакет и установленные LuCI-модули удалены;
- файлы и ключи состояния удалены;
- настройки UCI удалены;
- изменения сети применены;
- интерфейс `tailscale0` отсутствует;
- в проверенном ручном автозапуске не осталось ссылок на Tailscale.

Код выхода: `0` — проверки пройдены; `1` — ошибка удаления или остатки; `2` — отмена, неподходящая система или ошибка предварительной проверки. `--reboot` действует только при коде `0`. Повторный запуск допускается: уже отсутствующие пакеты и файлы не считаются ошибкой.

## Особые случаи

- Несохранённые изменения UCI `network` или `firewall` блокируют запуск, чтобы случайно не сохранить чужие изменения.
- Произвольные пользовательские скрипты не вырезаются автоматически. Ссылки на Tailscale в `/etc/rc.local`, `/etc/crontabs/*` и других `/etc/hotplug.d/iface/*` выводятся как остатки с конкретным путём. Убери соответствующие команды вручную и повтори запуск.
- Секции с другими именами, нестандартные пути установки/состояния и пользовательские службы требуют отдельной проверки. Скрипт не обещает их автоматическое удаление.
- Если Tailscale встроен в read-only образ прошивки, пакет или бинарный файл может остаться. Отчёт не покажет полный успех, если команда по-прежнему доступна.
- Скрипт не вызывает API панели управления и не удаляет серверную запись устройства. Это отдельное действие в панели Tailscale / RemoteRouterich.
- Не переназначает DNS наугад: если ранее Tailscale менял нестандартную конфигурацию DNS, проверь её отдельно.

После перезагрузки:

```sh
ip link show tailscale0
```

Ожидается `Device "tailscale0" does not exist.`

## Проверка разработки

Версия 1.0.1 исправляет слишком короткое ожидание остановки процесса в версии 1.0.0. Синтаксис проверяется POSIX shell. Сценарии с подставными командами и временной файловой системой проверяют удаление через apk/opkg, повторный запуск, ошибки пакета/файлов/UCI/firewall, остатки автозапуска, условия перезагрузки, медленное завершение процесса, необходимость SIGKILL и снятие регистрации procd. На настоящем роутере скрипт при разработке не запускался.

Источники: пользовательский файл «удаление ТС.txt»; [OpenWrt: Tailscale](https://openwrt.org/docs/guide-user/services/vpn/tailscale/start); [Tailscale: удаление](https://tailscale.com/docs/features/client/uninstall).
